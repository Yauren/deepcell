# Decisions

Why the base app is built the way it is. Add a dated entry when the group decides something.

## 2026-11-10: MSVIII tutorial safety and resource consistency

- Freeze the simulation for the entire active tutorial, including action instructions, so taking time to read cannot cause a breach or hunger. Keep manual actions usable, and move one real wave enemy into a stationary shooting position to avoid blocking the first instruction.
- Persist a `tutorial_paused` flag in the existing settings table. Returning from another screen or reopening skips elapsed tutorial time, even if the player skipped the tutorial on Survivors. No schema change or DB_VERSION increase is needed.
- Reuse the existing HUD render assets for every resource price. Set explicit 24dp drawable bounds instead of using the much larger image dimensions, and keep upgrade-specific feature icons intact.
- Raise Mushroom Farm's per-bar payout from 3 to 5. Load both rooms' payouts and bar lengths from a new `floors.json` asset rather than hard-coding balance values in Kotlin. The existing ten-bar storage formula raises the farm's base capacity from 30 to 50; stored quantities are retained.

## 2026-11-07: base app

- **Course modules only.** The professor said to use only what the modules covered. See `AGENTS.md` and `docs/module-map.md`.
- **Dependencies: only `androidx.appcompat` and `androidx.core`.** Both are in every new Android Studio project. `androidx.core` provides `NotificationCompat`, which Module 8 uses. No other libraries.
- **Android Gradle Plugin 9.4.1, Gradle 9.6.0, compileSdk/targetSdk 37, minSdk 24.** AGP 9 compiles Kotlin by itself, so there is no separate Kotlin plugin. These versions match the SDK installed on the setup PC. If a groupmate's Android Studio is older, update Android Studio rather than downgrading the project.
- **Views move with `translationY`, driven by a `Handler`.** The modules don't cover Canvas or SurfaceView, so enemies are ImageViews inside a FrameLayout. The loop runs about every 33 ms. This is fine for a few dozen enemies; don't spawn hundreds.
- **One loop, two speeds.** Movement and spawning run every frame. Machines (Auto-Turret, Drill Rig) run once per second, so their strength is easy to read: "level = damage per second" or "level = progress per second".
- **Save in `onPause`, load in `onResume`.** Survivors and Settings write straight to SQLite, so the game screen reloads everything when it comes back. Purchases also save immediately.
- **Offline earnings use the last-pause time.** The same time is used when coming back from the Survivors or Settings screen, so automation keeps working for those few seconds too. Offline time is capped at 8 hours.
- **Enemies on screen are not saved.** If Android closes the app, the current wave restarts from the beginning. This keeps the save simple.
- **Breach keeps it simple.** Lose 25% scrap, restore the hatch, repeat the wave. Survivors are never killed.
- **Survivors only boost manual work.** This keeps the automation theme clear: only machines earn while you're away.
- **Reset save needs a CheckBox.** Deleting a save can't happen with one accidental tap. Play over an existing save needs a second tap for the same reason.
- **Settings are stored in SQLite, not SharedPreferences.** SharedPreferences isn't in the modules; a small `settings` table is. Reset save keeps the settings.
- **`POST_NOTIFICATIONS` permission request.** Not a module topic, but on Android 13+ notifications don't show without it. It is one call in `MainActivity`.
- **Platform `Switch` instead of `SwitchCompat`.** Module 6 teaches `Switch`.
- **Portrait only.** The layout follows the vertical sketch.

## 2026-11-07: graphics and UI rework

- **Rooms are a cutaway, still in a ListView.** Each row draws one room with a lift shaft on the left, so new floors are just new rows. The list background draws the shaft rails, so the shaft is continuous. A footer view adds earth below the deepest room.
- **Tap the room, not a button.** The whole room is the manual action, which leaves room for the art. Workers hop and a "+N" popup shows each payout.
- **Our bunker is on the surface.** Enemies fall towards it, and survivors with the Roof job appear on its deck. Tapping the bunker repairs the hatch.
- **Upgrades open in a sheet.** The rooms stay visible most of the time. A bottom tab opens its sheet; tapping it again or ✕ closes it.
- **(Replaced by the Blender rework below.) All art is vector drawables made from code-drawn shapes,** generated by `tools/art/gen_art.py` and `tools/art/gen_ui.py`. No bitmaps, no Canvas. Some backgrounds are larger than lint's 200×200 vector advice; there are only a few on screen, so this is acceptable.
- **Less text.** Resource names became icons, labels were cut to names and numbers, and help sentences were removed.
- **Original style.** The cutaway idea is common in idle games. The bunker, rooms, characters, palette and layout here are our own; don't copy art or layouts from other games.

## 2026-11-07: name changed to Deepcell

- The game is called **Deepcell** (the user's choice). Package `com.deepcell.game`, project folder `Deepcell`, database file `deepcell.db`.
- The starting bunker is called **Bunker Nine** in the story, so the painted 9 on the bunker stays. The player can still rename the bunker.
- The emblem is now a hatch wheel around a hexagonal cell with a downward arrow.
- Because the package changed, Android treats this as a new app. A build installed under the old name (`com.burrownine.game`) stays on a device until uninstalled, and its save is not carried over.

## 2026-11-07: Blender art rework

- **Scenes are rendered in Blender, not drawn as vectors.** The user wanted a darker, lamp-lit look with depth. Every scene is built by Python scripts in `tools/blender/` (no imported models or image textures): simple bevelled shapes, procedural noise for rust and grime, banded toon lighting (Shader to RGB), inverted-hull outlines and a facing-based rim light. `render_all.py` renders, `export_to_app.py` writes WebP files to `res/drawable-nodpi/`.
- **Renders are plain images in ImageViews.** No Canvas or game engine; the app only stacks ImageViews, as before. Moving parts (workers, enemies, guards, gear, lamp glow) are still separate views animated with tweens.
- **Automation is shown by swapping the room image** (`room_dig` → `room_dig_auto`) instead of overlaying a machine.
- **Interface panels are 9-patch PNGs** generated by `tools/art/gen_ui.py` (needs Pillow), so the cut corners stay sharp at any size.
- **(Replaced below.) Font was the built-in `sans-serif-condensed`.**
- WebP keeps the APK small (the renders are about 240 KB in total).

## 2026-11-07: lighting, framing, icons, logo and title screen

- **Rooms are lit by a few strong lamps**, not a general wash: each lamp throws a cone with hard toon edges and the space between lamps stays dark, so every room has a clear focus. Haze makes the cones visible.
- **Each room and shaft segment has a black frame with an inner shadow** (`np_cell_frame` 9-patch), so the cells read as separate boxes.
- **Survivors get a soft contact shadow** baked under their feet when exported, so they stand on the floor instead of floating.
- **Everything outside is seen at eye level.** The bunker was a top-down view; it is now front-on like the rooms, and the surface camera sits at eye level with rubble along the ground. The bunker is dark and backlit by the dusk sun; its door lamp, window slits and floodlight light the front, so it matches the surface.
- **Icons are Blender renders too** (`tools/blender/icons.py`): tabs, upgrades, settings and the automation gear. Small icons inside buttons (scrap, food) and back/close/skull stay vectors, because compound drawables need small intrinsic sizes.
- **Font: Barlow Condensed** (the user's choice), bundled in `res/font` under the SIL Open Font License. The logo wordmark is the ExtraBold weight, extruded in Blender.
- **New logo**: a steel hex badge with an amber hatch wheel around a glowing cell, above the DEEPCELL wordmark. The launcher icon uses the same rendered emblem.
- **The title screen is a slideshow of camera shots** (surface with the bunker, Scrap Dig, Mushroom Farm). Each shot pans slowly; between shots the screen dips into a blurred copy and back. The blurred copies are pre-rendered, so this works on every Android version without blur APIs. It is a first try; the user was unsure it would work and should judge it.

## 2026-11-07: animation, effects and sound

- **Animations are rendered frames played with `AnimationDrawable`** (Module 4 drawables), not tweens on a still image. `tools/blender/anim_sprites.py` poses the same models frame by frame (empties as joints at the hips, shoulders and head) and `export_to_app.py` writes the frames and the `animation-list` XML. No Canvas or game engine.
- **Workers stand in the room's work zone** (the user's call): diggers left of the scrap heap with the pickaxe landing in it, farmers along the grow tables. With no collector NPC yet, the player still taps the room to collect; each worker adds to the tap as before. Balance is unchanged.
- **Effects are rendered flipbooks too** (`tools/blender/vfx.py`): explosion, dust, spores, sparks. The muzzle flash is baked into the guard's fire frames so it always lines up with the barrel.
- **Roof guards stand on the deck.** The bunker camera now looks down 12 degrees (was 4), so the roof reads as a floor; guards are placed at fixed spots either side of the hatch, aiming outwards (left ones mirrored).
- **Sound effects are synthesised in code** (`tools/audio/gen_sfx.py`, numpy + ffmpeg to OGG). Blender has no sound synthesis, so it was not used for audio. Played with `SoundPool`; the Sound switch in Settings mutes them.
- **Movement is eased**: smoothstep drift and fading sine sway for enemies (purely visual: the timing of hits is unchanged), decelerate/accelerate for the upgrade sheet, overshoot for button presses and payout text. Constant spins stay linear.
- **Settings has a Main menu button** (the user asked for a way back). It returns to the title with `FLAG_ACTIVITY_CLEAR_TOP`; the game saved when Settings opened.

## 2026-11-07: storage, Collector, main menu, performance

- **Rooms produce by themselves into storage** (the user's design): each worker adds 1 progress per second, the Drill Rig adds its level in Scrap Dig. Full bars go into the room's storage (10 bars, +25 per Storage Racks level); work pauses while storage is full. Workers no longer add to taps.
- **Collecting**: tapping a room lends a hand (1 + tools level) and collects its storage. The **Collector** (Automation tab, 30 scrap, level = walking speed) walks into each room in turn, picks up the storage and walks back; with a Collector, offline output is collected too, otherwise it waits in storage. The storage chip pulses while something waits and turns red when full. Numbers are first guesses for the group to tune (`GameActivity`: `WORKER_RATE`, `STORAGE_BARS`, `STORAGE_PER_LEVEL`; `upgrades.json`).
- **Save version 2** adds `dig_stock` and `farm_stock` with `ALTER TABLE` in `onUpgrade`; older saves keep everything.
- **The Collector is drawn by the game loop**, not by a view animation: ListView re-binds rows every second, which cancelled long-running animations on row views. Each frame the loop places it from the trip's phase and time, eased in and out.
- **Main menu**: Continue (with a card showing the save), New game (asks for the bunker name in a dialog, warns before replacing a save), Settings. The name field is gone from the menu.
- **Title shots are 3D scenes with a subject in focus** (depth of field), rendered at 1080x2340 so nothing is upscaled: the bunker with a guard on the roof, a digger at the heap, a farmer at the grow table. Motion on top in the app: slow pans, drifting dust motes, drones crossing the surface shot.
- **Sound loudness**: every effect is normalised to the same level with a soft limiter in `gen_sfx.py` (they were up to 30 dB too quiet) and plays at full volume; the volume keys control game sound.
- **Icons get a sticker outline** (dark edge, warm-white rim) at export; HUD counters sit in pill chips; bottom tabs have labels.
- **Performance for low-end phones**: images moved from `drawable-nodpi` to `drawable-xxhdpi/xhdpi/hdpi`, so a low-resolution phone decodes a quarter of the pixels. Room rows use a ViewHolder and per-second updates touch only changed views (`FloorAdapter.refresh`) instead of re-binding the list. Effect views are reused. A **Detail** setting (Auto/High/Low) picks Low on weak phones (low-RAM flag, memory class 128 MB or less, four cores or fewer): no lamp flicker, storage pulse, dust/spore bursts, title dust/drones or blur crossfade, and a 20 Hz game loop.

## 2026-11-07: tutorial, harder waves, Collector job, turret, music

- **Tutorial** (the user's request): after naming a new bunker, a dialog asks Tutorial or Skip. Six steps (`ui/Tutorial.kt`): shoot a drone, dig and collect, recruit, jobs (Survivors screen), storage, upgrades. A card says what to do and an amber arrow points at the target; action steps wait for the action, explanation steps have Got it; Skip tutorial ends it. The step is saved in settings, so it carries across screens and restarts. The card sits low (over the bedrock) so the sky stays clear.
- **New game starts with one survivor on the Roof** and 15 food (enough for the first recruit). Recruits get a generated name (`Survivor.randomName`); the name field is gone.
- **Guards shoot by themselves**: together one shot every 1.6 s divided by the number of guards, 1 damage, at the drone nearest the hatch once it is in the lower 60% of the sky (so the player still has something to tap). They still fire with the player's taps too.
- **Waves grow** (`waves.json`): +8% enemies per wave (wave 11 has 1.8x wave 1), spawns 2% closer per wave down to 45%, each 10-wave cycle +50% HP and +8% speed, one more boss every second cycle. Order is shuffled per wave.
- **Breach sends you back a wave**: playing idle on the emulator reached wave 30 with 0 scrap, because a breach only replayed the wave with a repaired hatch. Now a breach also drops one wave, so a bunker that can't hold stops climbing.
- **Collector is a survivor job** (the user's call), not a machine. Any survivor on the Collector job walks the rooms; each extra one makes the walk faster. Save version 3 turns a bought Collector machine into a survivor on that job.
- **Jobs are explained where they are chosen**: tapping a survivor opens a job picker with each job's figure and effect; rows show the effect under the name and a swap icon on the job chip. Rooms with nobody in them show "No workers: tap to dig by hand. Assign one in Survivors." (tapping it opens Survivors).
- **Auto-Turret is visible**: Blender-rendered base and twin-barrel gun on the hatch dome; the gun turns to each target, plays a flash and recoil, and draws a tracer.
- **Explosion sound** plays at 40% (impact 60%): it stacks up when many drones die.
- **Music** composed in code (`tools/audio/gen_music.py`): menu "Down Below" (A minor, 70 BPM), gameplay "Hold the Hatch" (D minor, 112 BPM), boss "Command Drone" (E minor, 140 BPM, plays on every 10th wave). Seamless loops played by `ui/Music.kt` (MediaPlayer, crossfade), under the effects. A Music switch is in Settings.

## 2026-11-07: tutorial highlight, harder progression, new upgrades, boss bar

- **Tutorial targets glow**: a pulsing amber frame around the thing each step is about, plus the arrow. Cards show "Step 2 of 6", a short title and one plain sentence or two (the user found the first wording hard to follow).
- **Recruiting gets dearer**: 15 food for the first recruit, then x1.6 for every survivor already in the bunker (15, 24, 38, 61, 98, ...).
- **Real numbers in the rooms**: rooms draw at most four workers and the roof four guards, so each room shows a crew chip ("5 workers · +5/s") and the roof shows "+N" for guards not drawn. All of them count.
- **Harder**: enemies hit harder (scout 7, shrike 4, bomber 25, boss 70) and a little faster; waves +12% enemies and +4% HP every wave, +60% HP and +10% speed every cycle; guards shoot every 2 s (shared) until Guard Training; upgrade prices grow faster (x1.65 to x2.4 per level).
- **New upgrades**: Guard Training (guards shoot 15% faster per level), Work Shifts (each worker +1 work per second per level), Sprinkler (fills Mushroom Farm, works offline), Repair Arm (+level hatch health per second). Icons rendered in `tools/blender/icons.py`.
- **Wave banner** (Wave 7, plus "Command Drone incoming" on boss waves) replaces only the "Wave cleared" toast, which popped up every few seconds. Toasts stay for purchases, not enough scrap or food, recruiting, job changes, breaches, offline earnings and a full hatch, so the Toast lesson is still covered.
- **Boss health bar** across the top of the sky while a Command Drone is up.
- **Music was too quiet on phone speakers**: the game and boss mixes were mostly kick and bass, which phone speakers can't reproduce, and sat about 10 dB under the effects. The master now cuts the sub-bass, normalises to -15 dBFS, the melody and arpeggio are louder, the gameplay melody starts after the 4-bar intro, and the player volume is 0.8.

## 2026-11-07: economy, upkeep, prices

The user found materials too easy: maxed Spore Trays and tapping gave thousands of mushrooms, with nothing to spend them on.

- **Survivors eat**: 1 food per survivor every 40 s, also while the app is closed. At 0 food the bunker is hungry: workers stop (machines keep going), guards stop shooting, the food count turns red, rooms say "no food, stopped", and a toast with the alarm says so once. Offline, workers only work for the share of the time the food lasted. Tapping the farm still works, so the player can always dig out.
- **A tap finishes at most the current bar**, whatever the tool level; Better Shovels and Spore Trays now stop at level 5.
- **Food upgrades**: Guard Training and Work Shifts are paid in food (`"currency": "food"` in `upgrades.json`; the price button shows a mushroom).
- **Everything dearer**: base prices about doubled and growth raised (x1.9 to x2.5). Recruiting 25 food, then x1.9 per survivor (25, 48, 90, 171, 325, ...). A new game starts with 40 food (first recruit plus a few minutes of meals).
- **Boss bar moved** to the top right, level with the hatch label and the same size, so it no longer covers the sky.
